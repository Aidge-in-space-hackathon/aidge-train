# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project context

Student team repository for the **Challenge AIDGE** (embedded AI challenge, Oct 1 – Dec 31 2026; deliverables due 2026-12-31, jury defense 2027-01-14). The team is working on the **"AIDGE IN SPACE"** subject (Viveris / CNES):

- Goal: optimize imaging data bandwidth between a lunar rover and the space platform by running **neural-network image compression** on a space-qualifiable **CPU/FPGA** target.
- Model to port: **J. Ballé's learned image compression** ("End-to-end Optimized Image Compression", ICLR 2017, arXiv:1611.01704).
- Required toolchain: ONNX model → **Aidge** (ONNX → C code, unit operators) → **LoCod** (C → HLS/HDL accelerators) → deployment on an SoC board (PS = CPU, PL = FPGA fabric).
- Expected outcomes: measure compression performance, memory footprint and CPU load; optimize the model and the PL/PS interconnections of the auto-generated code.
- A separate prize rewards contributions upstream to Aidge itself.
- This repository (`Aidge-in-space-hackathon/aidge-train`, **public**) succeeds the private `EmmanuelG-tech/AIDGE-IN-SPACE` (branch `feature-----train-UI`). Scope: the training platform and the compression benchmark only; the reference notebook, the Aidge/LoCod port and the board work live in other repos. Team members launch, test and validate RGB trainings and configs, then optimize models with Aidge, from the Gradio UI (five numbered tabs: 1. Entraîner, 2. Suivre, 3. Tester, 4. Valider, 5. Optimisation Aidge), on a GPU server (RTX 2060 SUPER, 8 GB) deployed by CI/CD (GitHub Actions + Docker Compose). Requirements, roles and roadmap: `docs/cahier_des_charges.md` (validated 2026-10-29); read it before planning a feature.

Full challenge description: the challenge brochure (page 6 is this subject) and the related ERTS 2026 Aidge paper (HAL hal-05513843) are kept in the old private repo, not here: this repo is public, so no third-party documents. `Ressources/img/` only holds the README figures.

## Repository state

On Windows, set `PYTHONIOENCODING=utf-8` when running scripts from the shell (French labels with `é`, `≈` crash the cp1252 console otherwise; the CLI entry points reconfigure stdout themselves).

- The reference notebook `balle2017_end2end.ipynb` is **not** in this repo (it stays in the old one). `aidge_in_space/` duplicates its model/coder code on purpose and keeps its checkpoint format and layer names; comments that cite "cellule N du notebook" refer to that external notebook. `data/` and `outputs/` are git-ignored.
- `aidge_in_space/` — compression benchmark (Gradio UI + CLI) used to justify the on-board strategy:
  - Run: `.venv\Scripts\python -m aidge_in_space.app` (http://127.0.0.1:7860; Docker: `docker compose up app`). CLI: `python -m aidge_in_space.bench --list` / `--codecs a,b --images N --mode gris|rgb --points P [--backend torch|onnxruntime|aidge] [--real-rate]`, writes `outputs/bench/<name>.csv` which the UI reloads. Tests: `python -m pytest tests`; one test: `python -m pytest tests/test_jobs.py::<name> -q` (`-k <pattern>` to filter).
  - `codecs/`: plugin registry — every module defining `codecs()` (returns `Codec` instances) is auto-discovered; tests in `tests/test_bench.py` parametrize over all registered codecs. `base.py` defines `Codec`/`Level`/`Result` and `LearnedCodec` (padding, encoder backend, real arithmetic-coded or estimated rate, decode check); everything that depends on the entropy model (on-board module, tables, encode/decode of latents) lives in a `coding.LatentCoding` subclass assigned to the codec's `coding` attribute (`FactorizedCoding` default, `HyperpriorCoding` for bmshj2018-hyperprior) — no `isinstance` dispatch on models. Models expose `in_ch`, `N`, `M`, `pad_multiple`, `downsampling`, `g_a`, `g_s`. `classical.py` (Pillow JPEG/JPEG 2000/WebP), `balle2017.py` (one codec per series = architecture + run name, from `outputs/checkpoints/bls2017_c*_N*_lambda*.pt`; each λ is a level; checkpoints without a `run` key, i.e. the notebook's, keep their key and label), `bmshj2018.py` (CompressAI pretrained factorized/hyperprior weights downloaded to `outputs/weights/`, architectures reimplemented in `nn.py` with CompressAI key names — CompressAI itself has no Windows wheel and is not a dependency).
  - `nn.py` models/GDN/entropy models; `entropy.py` arithmetic coder + per-symbol tables (escape + 20-bit bypass); `backends.py` runs the frozen-GDN `g_a` on torch / onnxruntime / Aidge (ONNX cached in `outputs/onnx/` by weight fingerprint, 1 thread); `profiling.py` per-layer MAC/params/activations of the on-board part (`g_a`, plus `h_a`+`h_s` for the hyperprior); `metrics.py` PSNR, MS-SSIM, BD-rate.
  - `entropy.encode_symbols`/`decode_symbols` run single-thread numba kernels (`@njit(cache=True)`, tables flattened once in `CdfTables`), byte-identical to the Python classes, which stay the reference and the fallback without numba (`entropy.NUMBA`, also for totals > `NUMBA_MAX_TOTAL`); `entropy.warmup()` compiles them from `LatentCoding.tables()`, outside the timed section. `Result.timings["codage entropique"]` (real rate only) is not a CSV column. numba 0.68.1 is pinned (it caps numpy < 2.6); Docker sets `NUMBA_CACHE_DIR` under `~/.cache`. Tests: `tests/test_entropy.py`.
  - Timings run on `backends.THREADS` (1) thread: g_a via the runner, entropy coding/hyperprior/decoding inside `backends.limited_threads()`. Runner cache is LRU (`MAX_RUNNERS`), ONNX exports are atomic (tmp + rename) and pruned to `MAX_ONNX_FILES`. Benchmark campaigns never overwrite an existing CSV (`bench.campaign_name`). MS-SSIM needs a side ≥ `metrics.MS_SSIM_MIN_SIDE` (176), NaN otherwise.
  - Gray mode with RGB-only models replicates the gray image on 3 channels (flagged in results). Aidge CPU backend is a slow reference implementation (~40x PyTorch); `aidge_core` must be imported before `aidge_backend_cpu` (DLL dependency on Windows).
  - The Tester tab derives the image mode from the model (`app.model_mode`); only the Valider tab has a mode radio. Measurement options, on-board cost, help and « Recharger les codecs » live in closed accordions.
  - Gradio 6: `theme`/`css` go to `launch()`; `elem_classes` of a `gr.Markdown` lands on both the `.block` wrapper and the inner `.prose`, so CSS must say which (`.block.hint`, `.prose.hint`); dropdowns updated by callbacks use `.input` (user-only) to avoid change loops. `gr.Dropdown` without `value` shows its first choice, so set `value` and the dependent menus together.
- Environment, two equivalent ways (dependencies in `requirements.txt`):
  - venv: `powershell -ExecutionPolicy Bypass -File scripts\setup_venv.ps1` (Windows) or `sh scripts/setup_venv.sh` (Linux/macOS), then `scripts\lancer_plateforme.bat` / `scripts/lancer_plateforme.sh`. PyPI torch is CPU-only on Windows; CUDA via `--index-url https://download.pytorch.org/whl/cu126`. `requirements.txt` still lists JupyterLab (leftover from the notebook).
  - Docker: the image **contains the code** (`COPY . /workspace`, so CI can publish it; `.dockerignore` excludes `data`, `outputs`, `docs`, `Ressources`, `locod`, `.env`), and the local compose files still mount the repo on `/workspace` over it. `docker compose up --build` starts the platform (app + worker, CUDA image `aidge-in-space:gpu`, only the worker reserves the NVIDIA card) on http://localhost:7860. Without an NVIDIA card the worker cannot start: use the venv (`docker-compose.cpu.yml` was removed on purpose). The Dockerfile's default `CMD` is the app. Production compose files (`docker-compose.prod.yml`, `docker-compose.prod.gpu.yml`) pull published images and are never used locally.
- Aidge 0.10.1 (`aidge-core`, `-backend-cpu`, `-onnx`, `-export-cpp`, `-quantization`) is installed from PyPI via `requirements.txt` (wheels exist only for Windows and Linux x86_64). API notes for this version: `aidge_onnx.load_onnx(path)` takes no `verbose` kwarg; inference = `model.compile("cpu", aidge_core.dtype.float32, dims=[[...]])`, `aidge_core.SequentialScheduler(model).forward(data=[aidge_core.Tensor(np_array)])`, output via `model.get_ordered_outputs()[0][0].get_operator().get_output(0)`. Conv + Sqrt + Div (frozen GDN) import and match onnxruntime (~1e-7).
- Tests: `tests/` (pytest) cover the benchmark and the training platform (`test_bench.py`, `test_training.py`, `test_jobs.py`, `test_ui_training.py`, plus a check that every module, class, function and method of `aidge_in_space/` has a `"""!` docstring, `test_every_definition_has_a_doxygen_docstring`); about 325 tests, ~4 min, of which `test_optim.py` ~1.5 min (skips depend on which checkpoints and weights are present, since `test_bench.py` parametrizes over the real codecs); run in CI on every pull request, inside the CPU image (`.github/workflows/ci-cd.yml`).
- API docs: Doxygen (`Doxyfile`, main page `docs/mainpage.md`, output `docs/html/`, git-ignored). Published to GitHub Pages by `.github/workflows/docs.yml` on push to `main`. Docstring convention for all package code: `"""! @brief ...` with `@param`, `@return`, `@throws`, `@copydoc` using fully dotted names (`@copydoc aidge_in_space.codecs.base.Codec.run`; `Codec::run` does not resolve); constants and attributes (including `self.x` in `__init__`) get a `## ...` comment on the line above. ## Training platform

Web UI (tabs 1. Entraîner, with the « Ajouter des images » section, and 2. Suivre in `ui_training.py`; Suivre lists `train` jobs only, via `JobStore.list_jobs(kind=...)` / `visible_jobs(store, kind)`, while `new_done_jobs` and the codec reload still look at every kind; `build_tabs()` returns a `connect()` called by `app.build()` once tabs 3. Tester and 4. Valider exist) + SQLite queue + worker + training CLI. The UI never trains: it writes jobs, the worker runs each one in a subprocess. Contract and details: `docs/conception_entrainement.md` (source of truth). Team user guide: `docs/guide_interface.md`.

- Run (Windows): `scripts\lancer_plateforme.bat` opens windows "AIDGE - worker" and "AIDGE - interface", polls http://127.0.0.1:7860 (`AIDGE_ATTENTE_MAX` s, default 120), opens the browser; no `.venv` -> points to `setup_venv.ps1`. `scripts/lancer_plateforme.sh` is the Linux/macOS equivalent. If port 7860 is taken by another program, the interface window shows a port error and the browser may open that program.
- Manual: `python -m aidge_in_space.worker [--poll S] [--once] [--db PATH]` + `python -m aidge_in_space.app`.
- Train CLI: `python -m aidge_in_space.train --config FILE.yaml [--out DIR] [--device auto|cpu|cuda]` (no DB) or `--job-id N [--db PATH] [--watch-stdin]` (queue job, status `running` set by the worker). The versioned `configs/` folder only holds `configs/optim/` (Aidge optimization examples): train's `--config` takes any YAML of `TrainConfig` fields. The UI presets live in `training.config.PRESETS` (gray only for now; the UI mode radio chooses gray or RGB).
- Docker: `docker compose up app worker` (NVIDIA card required, see Environment above). The `app` service runs the CUDA image but reserves no GPU: the benchmark measures on CPU, 1 thread on purpose. The worker has `stop_grace_period: 90s` so a training can checkpoint (worker `STOP_TIMEOUT_S` = 60 s). `docker-compose.gpu.yml` no longer exists.
- Env vars: `AIDGE_RUNS_DIR` (default `outputs/runs`, `/runs` in Docker), `AIDGE_UI_HOST` (default 127.0.0.1), `AIDGE_UI_USERS` (`login:pwd,login2:pwd2`, mandatory if host is not local), `AIDGE_UI_BIND` (Docker: host address publishing port 7860), `AIDGE_MAX_UPLOAD_MB` (default 500), `AIDGE_ATTENTE_MAX` (launcher wait, s).
- Architecture: `training/` package (`config.py` `TrainConfig` + YAML + `PRESETS` + `schedule_for`, no torch; `loop.py` `train()`, patch bank, checkpoint, resume; `imaging.py` `to_8bit`); `jobs.py` `JobStore` (SQLite jobs/metrics/workers, `DELETE` journal not WAL, `STATUS_LABELS` in French); `worker.py` (claims jobs, log in `RUNS_DIR/<id>/train.log`, heartbeats, final status from exit code); `train.py` CLI; `ui_training.py` (pure functions + thin Gradio adapters in `build_tabs()`); `ui_style.py` (`THEME` and `CSS` passed to `launch()`, plus the `header`, `intro`, `card` and `hint` layout helpers used by all tabs; system fonts only, no network, and CSS colors come from Gradio theme variables so dark mode follows).
- Exit codes of `train`: 0 done, 1 failed, 2 invalid config, 3 cancelled, 4 stopped (shutdown, status `interrupted`, resumable). Statuses: queued, running, done, failed, cancelled, interrupted; requeue from the last three resumes from the checkpoint.
- Checkpoints: `--config` writes `bls2017_c{in_ch}_N{N}_lambda{λ}.pt` (same name as the notebook), UI jobs add `_run{id}`; keys `state_dict, cfg, history, step, optimizer, run{job_id,name,author,commit,date}`. Pass `--out` or rename the file so as not to overwrite the notebook's checkpoint (a first test did; renamed `bls2017_c1_N128_lambda2048_test.pt`).
- Data: training sets in `data/train/<set>/`. The « Ajouter des images » section also downloads ready-made sets from `dataset_catalog.CATALOG` (UC Merced, Curiosity rover, DFKI lunar analogue, Imagewoof, DIV2K valid; URL, SHA-256 and license pinned per entry, a changed source file is refused and the entry must be updated). The app process downloads, not the worker; one download at a time (`concurrency_limit=1`). Tests use `file://` entries, no network. Oxford Pets/Flowers (`robots.ox.ac.uk`) were unreachable when the catalog was built. Upload is all-or-nothing and never overwrites (`_2` suffix); zip max 10 000 files, unzipped size <= 2x `AIDGE_MAX_UPLOAD_MB`. 16-bit images are scaled on their max to 8 bits (`training/imaging.to_8bit`). First training downloads Kodak (24 images, network needed; first quick test 271 s, then ~31-75 s on CPU); offline without Kodak, eval falls back to training images with a warning.
- Traps: SQLite locking is unreliable on a Windows folder mounted in Docker, hence the `runs` named volume; never mix a venv UI with the Docker worker (different DBs). A running training slows the PC and skews bench timings. `images.py` (bench) still converts 16-bit images without scaling (saturates): known limit. The stdin watcher thread must use `os.read(0, 1)`, not `sys.stdin.buffer.read` (crashes Python at exit on Windows). `lancer_plateforme.bat` is ASCII + CRLF on purpose. `AIDGE_UI_USERS` is still required as soon as `AIDGE_UI_BIND` is not local, even behind Authelia (reading identity from the `Remote-User` header is on the roadmap).

## Aidge optimization

Tab 5. Optimisation Aidge (`ui_optim.py`), jobs of `kind` `optim`, package `optim/`. Contract, spike results and PL performance axis: `docs/conception_optimisation.md` (source of truth). Spike LoCod/Bambu: `locod/spike/README.md`.

- CLI: `python -m aidge_in_space.optimize --config FILE.yaml [--out DIR]`, `--job-id N [--db PATH] [--watch-stdin]`, or `--analyze FILE.yaml` (JSON on stdout, what the Analyser button runs in a subprocess). Same exit codes as train. Examples: `configs/optim/`. Results: `outputs/optim/<id>/` (`report.json`, `calib.npz`, `fp32/export`, `mixte/export`, `mixte/locod/main.c`); `<id>.tmp-PID` while running, invisible to readers.
- Tab layout = five numbered steps for non-expert students: left column 1. Modèle, 2. Recette (only `mixte` checked; clipping, per-channel, counts, export, indicative series in a closed « Réglages avancés »), 3. Analyser ou lancer (series name next to the buttons); right column the Analyse card and 4. Suivre les optimisations, so a launched job is visible without scrolling; below, 5. Comparer les variantes (readable `summary_table` with verdict, `variants_table` with every technical column folded in « Détails »), a single « Télécharger le code » zone (all reports, CLI ones included; picking a job preselects its file) and the `HELP_MD` glossary accordion. Empty states (`sources_hint`, `calibration_hint`, `NO_JOB_YET`, `results_hint`, `bd_hint`, `files_hint`) say what to do; `optim_banner` adds a warning when `aidge_core` is missing from the UI environment (`importlib.util.find_spec`, no import) and `friendly_error` translates that error for Analyser. Plain-language verdicts and export states live in `optim/results.py` (`variant_verdict`, `export_text`, `locod_text`, used by `summary_markdown` too).
- Job tracking lives in tab 5, not in Suivre: step 4 (`optim_jobs_table`, `optim_job_details`, `optim_job_summary`, `current_stage` = last `stage` metric) with Annuler / Relancer through the shared `ui_training.cancel_job` / `requeue_job` / `job_action` (an optim job stops at the end of its current stage and restarts from scratch). Lancer shows `launch_message` and selects the new job in that section; reports are reread when the set of done optim jobs changes. The detail shows the selected job's variants (`results.report_for_job` adds `_dir`, like `read_reports`); the periodic tick refreshes it but never touches the download menu, only a pick does.
- Recipes: `fp32`, `int8` (Aidge 0.10.1 cannot quantify `Sqrt`: `quantize_network` only logs and returns, so `ptq.try_int8` must report `sans_effet`, never a success), `mixte` (default in the UI: each conv quantized alone, GDN float).
- `optim/config.py` and `optim/results.py` import neither torch nor Aidge (tested); the plugin `codecs/aidge_variants.py` discovers variants without Aidge. A variant persists as a recipe (checkpoint + config + `calib.npz`, rebuilt deterministically): `load_model_folder` loses tensor types on a quantized graph.
- Export traps (Aidge 0.10.1), all handled in `ptq.py`/`export.py`: `set_dataformat(nchw)` before `compile` and `dformat="nchw"` at export, otherwise the binary is silently wrong (43-47 % right); `dtype="float32"` even for the mixed graph; `Dequantizer` replaced by `Cast` + `Mul` (else `Select input out of range`); segment nodes prefixed (same names otherwise); `export()` mutates its graph, so rebuild one; it writes `exported_graph.mmd` to the cwd; `model_prequantized=True` gives a wrong binary. A mixed graph needs one inference before the memory plan.
- Export check is blocking: under `export.EXPORT_MIN_IDENTICAL_PCT` (99 %) of symbols identical to the Aidge graph of the same recipe, the variant fails. The rate against PyTorch is informative only. BD-rate needs 4 levels and monotonic curves, otherwise it is refused with a reason (`evaluate.bd_series`).
- `optim/export_c.py`: pure C generator for LoCod, reusable (imports only numpy, aidge_core, aidge_quantization), reads the quantized graph only, unknown nodes raise `ExportCError`. LoCod takes one C file, renamed `main.c`, no `-I`, finds accelerators by grepping `FPGA(` (so never write that text in a comment of the generated file). `locod/verifier_bambu.sh`: manual proof through Bambu.
- `optim/memory.py` traps for tests: a fresh model has identical GDNs that ONNX merges, which falsifies memory figures: perturb every parameter.
- Migration: `jobs.SCHEMA_VERSION` 2 adds `kind`; no way back, an older image refuses the database (`docs/deploiement.md`).
- Tests: `tests/test_optim.py`; `-m "not slow"` skips the ones that quantify or compile. `test_bench.py` also parametrizes over real variants in `outputs/optim`. On a machine with non-monotonic checkpoints, `test_levels_increase_rate` fails for those series.

## CI/CD and deployment

- `.github/workflows/ci-cd.yml`: on pull requests and on push to `dev`, validates every compose file, builds the CPU image, runs `pytest` inside it and checks that the app answers and the worker stays up. On push to `main`, also publishes `ghcr.io/aidge-in-space-hackathon/aidge-train` (`cpu-<sha>`, `gpu-<sha>`, `latest`, `gpu`) and, if the repo variable `DEPLOY_ENABLED` is `true`, deploys with `scripts/deploy.sh` on the self-hosted runner labelled `aidge-deploy` (VM on the homelab, `/opt/aidge-train`, project `aidge-train-prod`, health check with `--wait`, automatic rollback). `.github/actionlint.yaml` declares that label for actionlint.
- `.github/dependabot.yml`: weekly update PRs for pip, GitHub Actions and the Docker base image. Minor and patch updates are grouped per ecosystem; for pip and Actions, the `automerge` job of `ci-cd.yml` merges them once `test` passes. Major updates and Docker stay manual. These merges use `GITHUB_TOKEN`, so they trigger no publish or deploy: the next human merge to `main` (or a manual run of the workflow) ships them.
- The repo is public: never weaken the `if:` guards of the deploy job, and keep it the only job on the self-hosted runner. Guide: `docs/deploiement.md`.
